Why I moved my Codex default to GPT-6.1 Terra

November 4, 2026

I moved my Codex main session from GPT-6.1 Sol at high to GPT-6.1 Terra at medium. Sol is still in the setup for complex development. Astra still gets the hard judgment calls, and Luna still handles bounded work.

The decision took longer than the two lines it changed. I first kept Sol, then looked at a computer-use chart I had not given enough weight. The resulting setup is a bet about the mix of work in my main session, not proof that Terra is better at everything I do.

The chart I had underweighted

OpenAI's Terra launch announcement includes Agents' Last Exam, a benchmark of professional tasks performed with software. Its examples range from 3D modeling to reviewing animated film.

On the published chart, Terra at max reaches 60.0%, compared with Sol at max at 58.6%. The points are close, and this is the vendor's evaluation, not my own. The cost axis matters too: Terra's points sit substantially to the left of Sol's. OpenAI also reports that Terra completed tasks more than three times faster than Sol and Astra on this evaluation. That's a result for those tasks, not a general multiplier I can apply to every Codex session.

I had treated Terra as a model for small, fast jobs and visual work. The chart supports a broader case: it can handle substantial work across applications. My main session does more than code, so that matters.

The numbers that still favor Sol

The other chart I looked at points in a different direction. Artificial Analysis's Intelligence Index compares a mix of evaluations, not the same set of tasks as Agents' Last Exam:

Sol leads at each matched effort, though that doesn't mean it wins every coding task. I am accepting a trade when I lower both the model and the main session's effort. My previous default was Sol at high; Terra at medium scores 38 against Sol high's 50 on this index. That's a cross-effort comparison between the two settings I actually chose, not a controlled test of model difference alone.

I also ran one small comparison. I gave each model the same JSONL aggregation CLI task at high effort, then ran six independent black-box tests against each implementation. Both passed all six. That's a useful check that neither failed this particular exercise. It is not a benchmark of my repositories, a measure of latency, or evidence that the models are interchangeable on complex development.

Price is a rate, not a finished task

At standard API rates, Terra costs $1 per million input tokens and $5 per million output tokens; Sol costs $2 and $10. Cached input is $0.05 and $0.10 respectively. Those are per-token prices, not the cost of completing a job. Extra tokens, retries, or review can erase some of the difference. OpenAI's model catalog lists the current API rates.

Codex subscription usage and Codex credits are a separate system. I can't turn the API price ratio into an exact number of sessions or a prediction of my bill. OpenAI does say that, in Work and Codex, the same allowance goes substantially further with Terra than with Sol; the amount still depends on the task and how it runs. The computer-use chart's dollar figures are evaluation costs, not my subscription charges.

The actual changes

The configuration now sets:

model = "gpt-6.1-terra"
model_reasoning_effort = "medium"

I updated global AGENTS.md to describe the same default and to reserve Sol at high for complex codebase work, long technical tasks, difficult debugging, and complex orchestration. The existing specialist roles remain:

The distinction between the two files matters. config.toml selects the configured default. AGENTS.md records how I want to choose and delegate; it does not inspect each task and automatically switch the main model. For a difficult development session I still need to select Sol, or explicitly choose it for a suitable subagent. Existing sessions may still need their model picker checked.

A default to test

The case for Terra is strongest when I combine the kind of work my main session does with the computer-use results and its lower token price. The case for Sol is still strong for harder technical work, and the broader index is a reason to keep that escalation path visible.

I haven't measured a representative set of my own sessions yet. If Terra needs enough correction or review on real projects to offset the speed and usage savings, I can change the default again. For now, this is the setup I want to try, with the limits of the evidence written down next to it.
