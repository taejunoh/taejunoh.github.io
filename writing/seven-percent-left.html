Seven percent left

November 16, 2026

On Thursday I added a rule for when Fable runs out. Once the weekly Fable limit is used up and a call to deep-reasoner fails, the main session keeps delegating but runs deep-reasoner on Opus until the reset. I had taken out the first draft's early trigger on purpose. The rule was meant to fire on a failure, not on a low bar.

Today one of my sessions said, while handing off to Codex:

another session, translated from Korean
Usage has room, but the Fable weekly limit only has 7% left, so if deep-reasoner is needed I'll run it on Opus.

No call had failed. The session switched with Fable still available, which is exactly the case I had decided against.

Not a stale copy

My first guess was an old rule. The early-trigger draft was live for a few minutes on Thursday, and a session that started in that window would carry it. So the assistant searched the transcripts for the sentence. Two sessions had said it, the one I saw and another in a different project. Both had loaded the current wording, "once the Fable weekly limit is used up," and neither had the old one.

So both sessions had the right rule and still switched early.

Two rules that meet

The fallback rule says when to switch. It never says not to switch before then. On its own that might be enough. But a second rule sits a few sections down: my usage reserve. It tells a session to stop ordinary work when a limit has 10% or less left, and the limits it counts include "a per-model weekly limit only when it matches the model doing the current work."

deep-reasoner runs on Fable. A session about to delegate can read that as Fable being the model doing the work, and 7% as under the line. Stopping would break the delegation rule, and the fallback offers a way to keep going. So it switches early and says so in one line, which is also what the fallback asks for.

This is my reading, not something the transcripts show. Neither session wrote down its reasoning. But the wording allows it, and it explains why two separate sessions landed on the same sentence. The 10% I took out of the fallback came back through another rule.

The fix

The reserve section is managed by another tool, so I didn't edit it. The fallback now ends with the part it was missing:

added to the Fable fallback in claude.md
Until a call actually fails, keep using Fable however little of its limit is left. The usage reserve's 10% threshold doesn't apply to the Fable limit, and a low Fable bar is not a reason to switch.

The rule now names the other rule it could be confused with. A rule that says when to act can be read as permission to act earlier, so it has to say when not to.

The intent behind it hasn't changed. The Fable limit is a cap on one model, not a reserve. Whatever is left of it this week is Fable I can still use, and switching early hands my hardest calls to a different model for nothing.

Still untested

This doesn't test the fallback itself. Nothing has failed yet. As I write this, Fable is at 93% for the week, so the first real failure may come before Thursday's reset. Sessions that were already open still hold the old wording until they re-read the rules file. The two that switched need to be told.
