Only the gaps

November 24, 2026

I asked my assistant whether Matt Pocock's skills would work for me. It's a popular set of agent skills: interviews that sharpen a plan, a test-driven loop, a debugging loop, code review, hand-off notes, retrospectives. Installing all of it is one command. The answer was yes, but not all of it.

Two kinds of skill

The repo splits its skills by who can start them. Some only run when I type them, like /grill-me. Others the model can pick up on its own when a task looks like a match. That split decided almost everything.

A skill I have to type can't collide with anything. If I don't call it, it doesn't run. A skill the model picks for itself competes with every other skill whose description fits the same task. My setup already has a debugging skill from two different plugins, a test-driven skill and a code review command. One of those plugins also tells the model to use any skill that looks relevant. Adding a third debugging skill means each session picks one of three, and different sessions pick differently.

That matters more than it sounds, because my rules depend on which skill runs. A hook watches for my design and debugging skills by name. When one starts, it reminds the session to hand the hard part to deep-reasoner, the subagent that does my reasoning (I wrote about why that reminder exists in Rules it couldn't follow). A new debugging skill with a different name would start without the reminder. Nothing would break that I could see. The hand-off would just stop happening in some sessions.

What I took

mattpocock/skills · 39 skills
taken, typed by me (8)
  grill-me, grill-with-docs     interview until every decision is settled
  handoff                       write the notes for the next session
  retro                         review a session for what to fix in the setup
  improve-codebase-architecture survey a codebase for structural fixes
  to-tickets, wayfinder         split big work into tickets
  setup-matt-pocock-skills      one-time setup per repo

taken because those call them (4)
  grilling, domain-modeling, codebase-design, writing-for-agents

left out, already covered (3)
  diagnosing-bugs, tdd, code-review

I skipped the other 24 for now. Eight are marked in progress by the author. Most of the rest serve workflows I don't have yet, like issue triage, course exercises or implementing from a ticket queue.

The eight I took fill gaps rather than adding a second way to do something. My rules say a lot about which model does what. They say almost nothing about the parts between me and the assistant: agreeing on what to build, handing work to the next session, and looking back at what went wrong. Three skills cover those.

Grilling works through a plan as a tree of decisions. Each round asks every question that can be answered now, with a recommended answer for each, and it doesn't start work until every branch is settled. My current design skill asks one question at a time. That's the pattern where a session made small calls on its own and never handed the design to deep-reasoner.

Handoff gives the notes a shape. It points to commits and specs instead of copying them, strips secrets, and names the skills the next session should load. Last week a session wrote hand-off files for Codex from scratch.

Retro does on purpose what I've been doing by accident. The last two problems I fixed, simulators piling up and switching off Fable early, surfaced because I noticed something odd and asked. Retro goes through a finished session with a fixed list: checks that could have caught a mistake, expensive tool calls, rules that don't change behavior.

Wiring them in

Two of the four supporting skills, grilling and codebase-design, are design work under another name. So the design hook now matches them too. A grilling session gets the same deep-reasoner reminder as my other design skills.

I copied the files at one commit instead of installing the plugin. The plugin updates itself, which also means the skill descriptions the model reads could change without my knowing. A copy only changes when I change it. The assistant read every file before copying. They're all plain instructions, with no scripts.

The copy itself went wrong the first time. A trailing slash in the copy command made macOS spill the files loose into my skills folder instead of into their own folders. That folder had only held folders before, so the stray files were easy to find and remove, and nothing else was touched.

One trap is specific to this site. The setup skill adds a section to a repo's CLAUDE.md. In this repo, that file is the claude.md you can read here, because macOS ignores the difference in case. Running setup here would publish its notes on my site, so I won't run it in this repo.

Not used yet

All of this is from reading, not from use. I haven't run a grilling session or a retro yet. The case for them rests on gaps I've already seen, not on results. I'll try /grill-me on the next design and /retro after the next long session, and write down whether either one caught something I would have missed.
